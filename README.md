# SuperCitycon

A retro 16-bit-palette **voxel city builder** for the browser. Three.js 0.169 +
Vite 5, ES modules, no TypeScript.

**Version 6.0.0** — see [`docs/V6_VERIFICATION.md`](docs/V6_VERIFICATION.md)
for the release classification and [`CHANGELOG.md`](CHANGELOG.md) for what changed.
The V5 record is kept at [`docs/V5_FINAL_VERIFICATION.md`](docs/V5_FINAL_VERIFICATION.md).

## ▶ Play it

**https://atiffhussainkhan.github.io/SuperCitycon/**

Click the link, and the city is live in your browser. Nothing to install.

**New here? Read [game/PLAY-GUIDE.md](game/PLAY-GUIDE.md)** — the controls, the
seven tools, the shop, every HUD meter and every panel, in one page. The game
also has it built in: press **H**.

Every piece of art and animation comes from the owner's own asset library.
Nothing is generated, redrawn or substituted.

```
game/     the game — source, art, tests, build
docs/     the requirements dossier this build implements (1,168 requirements)
tools/    the manifest builder and the browser acceptance harness
agents/   the five master bots that built it
```

## What V5 adds

V5 is a major-version upgrade of the city builder. It is not a new game and it
does not replace anything V4 did — every V4 feature still works.

| Area | What V5 adds |
|---|---|
| **Architecture** | one clock (CORE owns time), a fixed-timestep simulation, structured logging, a validated settings store, one key-binding table, an explicit teardown path, a diagnostics surface |
| **Save** | a versioned save format with a migration chain — a V4 save loads into V5, a newer save is refused rather than guessed at |
| **Presentation** | a pooled, instanced VFX service with nine effect kinds, wired to the game's own events; the audio mixer (built in V4 and never called) is now connected |
| **Gameplay** | the **hazard system**: multi-phase city crises with telegraphed escalation, a damage pipeline, mitigation from the city's own service coverage, and checkpoint integration |
| **Content** | a level-content pipeline — a level schema, three original levels, a validator with an offline CLI, and a service that loads a level into the live city |
| **Access** | remappable controls, reduced effects and shake, text scaling, high contrast, colour-blind indicators, keyboard navigation |

The full mapping, the verification evidence and what V5 deliberately does **not**
deliver are in [`docs/V5_UPGRADE_PLAN.md`](docs/V5_UPGRADE_PLAN.md) and
[`docs/V5_REQUIREMENTS_MATRIX.md`](docs/V5_REQUIREMENTS_MATRIX.md).

## The five master bots

The game was assembled by five agents working in parallel, each owning a
disjoint slice of the source tree. Their definitions are in [`agents/`](agents/)
and were installed to `~/.minimax/agents/`.

| Bot | Owns | Delivers |
|---|---|---|
| `sc-asset-curator` | `game/src/data/`, `game/public/assets/` | the 3D manifest, the curated 2D art and its manifest, the licence texts |
| `sc-world-content` | `game/src/world/`, `game/src/buildings/`, `game/src/data/` | terrain, water, nature scatter, the building catalogue, placement rules, library-model integration |
| `sc-simulation` | `game/src/economy/`, `game/src/mobility/`, `game/src/population/`, `game/src/services/` | treasury and budget cycle, road network and traffic, citizens and happiness, service coverage |
| `sc-interface` | `game/src/ui/`, `game/src/studio/` | the HUD, the camera rig, the tools, the building shop, the SCC Studio voxel editor |
| `sc-integration` | `game/src/main.js`, `game/src/core/`, `game/src/render/`, the build, the harnesses | the bootstrap, the frame loop, the input dispatch, the cross-domain wiring, the build, the acceptance harness |

`game/src/core/CONTRACT.md` is the binding contract between them: it defines
the shared `ctx`, the event bus, the asset and renderer services, and the exact
public API of every domain. Nobody changes another domain's public API.


## Run it

```bash
cd game

```

## Play the built game

```bash
cd game
npm run build        # -> game/dist   (local build: includes the 2D art)
npm run preview      # -> http://localhost:4173
```

The game must be served from the **root** of a host: the model and icon paths in
the manifests are absolute (`/assets/models/...`, `/assets/ui/...`).

**One copy of the game.** `game/dist/` is a build output and is deliberately
**not** committed — it is regenerated by `npm run build` in about ten seconds.
Every model binary is in the history exactly once, in
`game/public/assets/models/`. The raw library archives that were used to
curate the art are source material and live in `~/.minimax/asset-library`, not
here; the single exception is `kaykit-city-builder.zip`, which exists nowhere
else and therefore travels with the game.

## Licence position — read before publishing

| Asset set | Licence | Status |
|---|---|---|
| 3D models and animation (158 assets, 5 packs) | CC0-1.0 / MIT | **cleared to publish** |
| 2D HUD art (69 distinct images across 84 HUD records) | `unverified` | **NOT cleared — do not publish** |

So publication is a deliberate act:

| Command | Result |
|---|---|
| `npm run build` | a LOCAL build that contains the 2D art and says so (`dist/DO-NOT-PUBLISH.txt`) |
| `npm run build:cleared` | the SHIPPABLE build: the unverified 2D art is **stripped** and the build **fails** if any of it survives |

The cleared build loses no function — the HUD is complete and correct with zero
2D images. The full position, and what the publisher has to do, is in
[`game/LICENCE-REPORT.md`](game/LICENCE-REPORT.md).

## The requirements dossier

The build implements a source-traceable specification assembled from primary
sources. The dossier in [`docs/`](docs/) is the contract it was written
against:

| Path | What it is |
|---|---|
| `docs/SUPER-CITYCON-MASTER-REQUIREMENTS.md` | **The mega document.** Every requirement, all ten domain specifications in full, the consolidated source index, the stage matrices, the open questions and the ownership map. |
| `docs/00-research-brief.md` | the shared fact base and method contract all ten bots worked from |
| `docs/SOURCE-VERIFICATION.md` | every URL and video ID used, independently checked against the page's own title and channel — including the sources that turned out to belong to *other* games |
| `docs/requirements/` | the ten per-domain requirement specifications |
| `docs/transcripts/` | the retrieved transcripts of the verified sources |
| `docs/validation-report.json` | the machine-readable validation result |
| `tools/validate_requirements.py` | verifies the contract: sections, ID uniqueness, counts, per-requirement sourcing, foreign-source detection, QA-outcome quality |
| `tools/build_manifest.py` | walks every glTF/GLB scene graph and emits `game/src/data/manifest.json` — the only source of art paths in the code |

The dossier was produced by a primary-source sweep, frozen into a shared fact
base, then written by ten requirement-level bots each researching one domain
against primary sources under a fixed twelve-section contract, and audited by a
senior-review pass.
